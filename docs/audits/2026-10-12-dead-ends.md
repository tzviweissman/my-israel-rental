# Dead ends - 2026-10-12

Scheduled dead-ends audit, following `.claude/skills/dead-ends/SKILL.md`.
Method: static analysis only (route-table resolution, query-param reader
check, email/notification URL resolution, endpoint-to-caller sweep, import
graph, scheduler comparison), plus a read of everything that landed since the
last dead-ends audit (`2026-09-14-dead-ends.md`): the restaurants directory,
hand-built business pages, the owner page editor, and the order-form flow.
Nothing was clicked in a browser (see "Not checked").

**Headline:** five of the 14 Sep carry-overs are now fixed, including the
one flagged twice as a real moderation hole. The new surfaces are mostly
well-wired. One latent break (hand-built order page, delivery) and a handful
of orphaned capabilities, none user-facing right now.

## Broken: goes nowhere or errors

None found live.

**Latent, depends on production data I could not read:**

- **Hand-built order page, delivery.**
  `frontend/public/pages/blazin-boards/order-details.html:~96-103` builds the
  POST body for `POST /marketplace/order-form/{gig_id}/orders` with no `city`.
  `order-when.html:106` un-hides the **"Deliver to me"** chip whenever
  `settings.delivery_on` is true. The endpoint
  (`backend/routes/marketplace/orders.py:2063-2068`) answers a delivery order
  with 400 *"This store does not deliver there"* unless the business has
  `serves_nationwide` or the request carries a `city` in `biz.areas`. The
  React `OrderPage.jsx:160` does send `city`; the hand-built page does not.
  So: if Blazin' Boards has delivery switched on and is not nationwide, every
  delivery order from its page fails after the customer has filled in three
  steps. Pickup is unaffected. This is the "button renders in a state the API
  rejects" shape of the "Message on MyIsraelRental" bug.
  **Fix (build):** either add a city picker to `order-when.html` fed from the
  `areas` the `/order-form/{id}` response already returns, or, if the store
  delivers only locally, set `serves_nationwide` / the area list so the
  server accepts it. Check the live business record first.

**New this cycle**

- **`AdminEdit.certificate_valid_until`, `lat`, `lng`, `city`,

  have no editor. `RestaurantsTab.jsx:22` `EDITABLE` is only `name_en,
  name_he, certification, kashrut, phone, whatsapp, website, address`. The

## Verified working

- Route table: 66 routes in `App.js`; every literal internal link resolves.
- Query-param readers exist for every key links pass (`tab`, `view`, `with`,
  `section`, `welcome`, `details`, `highlight`, `tour`, `services`,
  `business`, `add`, `redirect`). Dashboard `ALL_TAB_IDS` covers every
  `tab=` any backend email or notification emits, including `network` with
  `view=requests|automations`.
- `/properties/vacation?area=` and `/services/jobs?category=` from emails:
  read by `Properties.js:211` and `JobsBoard.jsx:50`.
- Restaurants: `/restaurants`, `/restaurants/:city`, nav, footer, the
  `/businesses` tile, `KosherNearby` link; every filter the page can set
  (`city, neighborhood, region, category, kashrut, certifier, q, lat, lng`)
  is accepted by `GET /restaurants`. "Get listed", report, claim, and all
  admin queue actions (submissions, reports, claims, import, edit, add)
  have both UI and endpoint.
- Owner page editor: "Edit your page" button (`MyBusinessesTab.jsx:456`) only
  renders for slugs in the hand-built list; `PUT/DELETE .../page-edits`
  is owner-guarded and the editor calls exactly those.
- Hand-built pages: Blazin' and KasherMyBnb multi-step flows link only to
  pages that exist; Blazin' POST body matches `WebsiteOrderIn` for pickup.
- Email links: availability-extended, review request, jobs/requests/insights
  opt-outs, booking tracking, payment success/cancel all resolve.
