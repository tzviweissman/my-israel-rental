## Broken: goes nowhere or errors

### 1. Admin "Attention" queue's expiring-requests row navigates to a tab that does not exist
`frontend/src/components/admin/AttentionQueue.jsx:49` — the row reads
*"N requests expiring within 3 days with no responses"* and its `onClick`
calls `onNavigate('requests')` (line 106). `onNavigate` is
`setActiveTab` from `frontend/src/pages/AdminDashboard.js:76`. `AdminDashboard`
has **no `'requests'` entry** anywhere in `TAB_GROUPS` (lines 36-66) and no
`{activeTab === 'requests' && …}` render branch (lines 177-194) — the closed
set is `overview, listings, services, areas, bookings, users, chats,
smart-lists, import, settings, email-health`. Unlike the owner dashboard
(`frontend/src/pages/Dashboard.js:185`, fixed 2026-09-04), `AdminDashboard`
has no fallback validation on `activeTab` — clicking the row sets state to a
value nothing matches, so the tab-pill row shows nothing selected and the
content area below it goes blank. No console error, no 404; the admin just
sees an empty page.

**Fix:** either build a Requests admin tab (see #2/#3 below — there's a real
backend feature waiting for exactly this) and add it to `TAB_GROUPS`, or, as
a minimal fix, point this row at an existing tab and drop the false promise
of a dedicated requests view.

## Dead-end promises: destination lacks the affordance

### 2. "Report" on a request/offer promises human review; no human can ever see it
`frontend/src/pages/RequestDetail.jsx:469-474` — the **Report** button
(`t('requests.report', 'Report')`) opens a `window.prompt`, and on submit
`frontend/src/pages/RequestDetail.jsx:108-120` POSTs to
`/marketplace/requests/{id}/report` and shows the toast **"Thanks — we will
take a look."** (line 117, `t('requests.reported', …)`).

Nobody ever takes a look. The backend fully implements the review side:
`GET /admin/request-reports` (`backend/routes/admin/marketplace.py:274-335`,
returns reported/flagged posts with reasons, newest-first) and
`POST /admin/request-reports/{id}` (line 346-370, `hide`/`allow` actions,
records `moderated_by`/`moderated_at`). Its own docstring even calls out the
old bug this was meant to fix: *"a report button that files into a drawer
nobody opens is worse than no button, because it tells the person who
pressed it that somebody is looking"* (marketplace.py:249-251). But
**`rg -n "request-reports|posts_awaiting_moderation" frontend/src` returns
nothing** — no admin component calls either endpoint, and the `posts_
awaiting_moderation` count computed at `marketplace.py:266` (fed into
`GET /admin/attention`) isn't even read into a row in
`AttentionQueue.jsx`'s five-item list (lines 43-86). The queue exists, fills
up, and is invisible from every angle. This is the exact bug class the
backend comment describes, just not actually fixed on the frontend.

**Fix:** build the moderation queue view (a list of `admin_request_reports`
rows with Hide/Allow buttons calling the existing PATCH-equivalent POST) and
add a row for `posts_awaiting_moderation` to `AttentionQueue.jsx`. The whole
backend contract is already there and tested-shaped; this is a frontend-only
gap.

### 3. "N trading businesses not verified yet" has no way to find or verify them
`frontend/src/components/admin/AttentionQueue.jsx:66-76` — row text
*"N trading business(es) not verified yet"*, `go: 'services'`
(line 75). That tab renders `ServicesTab`
(`frontend/src/components/admin/ServicesTab.jsx`), which is deliberately a
thin table of **gigs** (title/business/category/area/price/status), not
businesses, with a title-only search box (line 97-100) and exactly two
actions: publish/unpublish a gig (lines 56-71, 185-194). It has no
"verified" column, no unverified filter, and no per-business action of any
kind — confirmed with `rg -n "unverified|verified"
frontend/src/components/admin/ServicesTab.jsx` (zero matches).

The backend has the write path fully built:
`PATCH /businesses/{business_id}/verified`
(`backend/routes/marketplace/businesses.py:764-782`, admin-only, sets
`verified`/`verified_at`) — but `rg -n "/verified\b" frontend/src` returns
nothing. There is no admin UI anywhere that can mark a business verified, so
the count the attention queue surfaces can only ever grow.

**Fix:** add a businesses list (or a "verified" column + toggle inside
`ServicesTab`, grouped by business) that calls the existing
`PATCH …/verified` endpoint.

### 4. "N published services with no photo" has no way to identify which ones
`frontend/src/components/admin/AttentionQueue.jsx:58-63` — same `go:
'services'` destination as #3. `ServicesTab`'s table (columns listed above)
has no photo indicator and no "missing photo" filter, so an admin who clicks
this row cannot tell which of the listed rows are the ones being counted —
they'd have to open each one individually. Softer than #1-#3 (the tab itself
is real and does list services), but the promise ("here's what needs
attention") isn't kept by the destination.

**Fix:** add a photo/no-photo indicator (icon or badge) to the `ServicesTab`
table, or a `?photo=missing` query param the tab reads on arrival.

*(By contrast, the "chats-unanswered" and "emails-bounced" rows in the same
queue land on destinations that do carry the signal — see Verified working
#8 — so this is specific to the Services-tab-backed rows, not a queue-wide
pattern.)*

## Orphaned capabilities

### 5. Admin moderation queue and business-verification endpoints, no caller
Both already covered above as the root cause of #2 and #3 — restated here
because they're the systematic version of the same bug:
- `GET /admin/request-reports` and `POST /admin/request-reports/{id}`
  (`backend/routes/admin/marketplace.py:274,346`) — no frontend caller.
- `PATCH /businesses/{business_id}/verified`
  (`backend/routes/marketplace/businesses.py:764`) — no frontend caller.

Both are admin-only and clearly meant to be used from a build console, not
externally — not "legitimately admin/external and fine to be uncalled" the
way, say, a webhook would be; these have no caller *anywhere*, admin UI
included.

### 6. `ThumbnailCarousel` (default export) unused
`frontend/src/components/ui/thumbnail-carousel.jsx:177-227` exports
`ThumbnailCarousel` as the file's default export — a full carousel-plus-strip
component. Only the named export `ThumbnailStrip` is imported anywhere
(`frontend/src/components/property/ImageGallery.jsx:4`); `rg -n "from.*
thumbnail-carousel"` across the repo shows exactly that one import.
`ThumbnailCarousel` itself is dead code, introduced in the 2026-09-06
gallery commit as leftover scaffolding from the ported source component.
Low priority — it's ~50 lines inside an otherwise-used file, not a whole
orphaned file, and does no harm sitting there.

**Fix:** delete the unused default export, or leave it — low stakes either
way; noting it for completeness per the methodology.

*No new orphaned model fields, unreachable enum values, or unregistered
scheduled jobs were found. Backend is unchanged since 2026-09-03's fixes, and
a fresh sweep (`asyncio.create_task` vs. every `*_loop`/`*_daily_loop`
function in `backend/`) confirms all scheduled work is still registered in
`backend/server.py:228-367`. `for f in frontend/src/components/**/*.jsx` and
the same over `pages/` found zero orphaned components (down from the 6
deleted in the 09-03/05 fixes).*

## Resolution (8 Sep 2026)

Fixed in the commit that follows this file:

- **#1 / #2** a new admin "Requests" tab (`RequestReportsTab.jsx`) drives
  the `GET/POST /admin/request-reports` moderation queue with Hide/Allow,
  reversible and recorded, same shape as the Services unpublish flip. The
  attention queue's "requests expiring" row now lands on it. `AdminDashboard`
  also gained the closed-set `activeTab` validation the owner dashboard
  already had, so a future bad `go` value falls back to Overview instead
  of a blank pane.
- **#3 / #4** `ServicesTab` gained Photo and Verified columns and a
  Verified toggle (`PATCH /businesses/{id}/verified`, already built,
  never called). The attention queue's "no photo" and "not verified" rows
  now pass a filter the tab applies on arrival, so the destination shows
  which listings, not just a tab that contains them somewhere.
- **#5 (orphan)** the KPI "Open requests" card now links to the new tab —
  it previously carried a comment explaining why it couldn't.
- **#6** the unused `ThumbnailCarousel` default export is deleted.

**Not verified by clicking** — no `backend/.env`, local MongoDB, or
frontend `node_modules` in this environment. Verified instead by full
manual re-read of every touched file and call site, and Python `ast`
parse of the backend changes. Flagging for a follow-up pass with a live
stack.
