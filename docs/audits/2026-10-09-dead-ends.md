## Dead-end promises: destination lacks the affordance

1. **Restaurant admin pin editor shipped backend-only.** Commit `a61bd4e`
   (10-09): "admin can set a pin (lat/lng) on a hand-added place".
   `backend/routes/restaurants.py:186-190` `AdminEdit` accepts `lat`, `lng`,
   `city`, `neighborhood`, `categories`, but
   `frontend/src/components/admin/RestaurantsTab.jsx:21` `EDITABLE` is only
   name_en, name_he, certification, kashrut, phone, whatsapp, website, address
   (verified). `POST /admin/restaurants/pin-missing` (`restaurants.py:278`) also
   has no button. **Fix (build):** add lat/lng (and city/neighborhood/categories)
   inputs to `Editor`, and a "Pin missing" button.

2. **Restaurant "Get listed" promises an email that is never sent.**
   `restaurants.sent` (`locales/en.js` ~4928): "Thank you. We check the hechsher
   and add you; we will email you when you are listed."
   `POST /admin/restaurants/submissions/{id}/approve` (`restaurants.py:416-440`)
   has no email or notification (verified: no email call in that range). The
   required `contact_email` is collected and unused; the claim-approval path
   (~line 552) does send one. **Fix:** send an approve email (and a short
   rejection note), or change the copy to drop "we will email you".

3. **Setup checklist "Set your availability" is wrong both ways.**
   `backend/routes/onboarding.py:205,234` computes done as
   `available_from or ical_url`. (a) `ical_url` is not a stored field; feeds
   live in `ical_urls` (`routes/ical.py:34`), so connecting iCal never ticks it.
   (b) `AddPropertyModal.jsx:253` pre-fills `available_from` with today, so the
   row is ticked the moment a listing exists (verified both). **Fix:** test
   `ical_urls` non-empty; stop counting the default date (e.g. require
   `available_to`), or drop the row.

4. **Saved-search alert promise skips bulk and admin-created listings.**
   `filters.saveAsAlertTooltip` (en.js:2892) "We'll email you when a new place
   matches your filters"; `zeroResultsBody` (2894) "...within 24h of a fresh
   listing". `match_property_against_searches` is called only from
   `routes/properties/crud.py` and `routes/bookings/cancel.py` (verified).
   Inserts in `routes/bulk_upload.py:406`, `admin_import/properties.py:214`,
   `admin_import/quick_add.py:124`, `admin/properties_bulk.py:335` never call
   it. **Fix (build):** call the matcher after those inserts, or add a daily
   sweep over listings created in the last 24h.

5. **Feature-library "Try it" opens a blank pane for non-listers.**
   `frontend/src/data/featureLibrary.js:117,131,145` use
   `cta: '/dashboard?tab=properties'`, rendered by `FeatureDetail.jsx:102` for
   every visitor. `Dashboard.js:492` renders the pane only for
   `isPropertyLister` (owner/manager/admin) with no else-branch. **Fix:** add a
   `properties && !isPropertyLister` empty state (pattern at `Dashboard.js`
   435/524/571/586) linking to `/join`, or point those CTAs at `/join`.
