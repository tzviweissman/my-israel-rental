Scheduled dead-ends audit, following `.claude/skills/dead-ends/SKILL.md`. Three
parallel passes (forward link resolution, backward promise-to-destination,
orphaned capabilities) cross-referenced against `frontend/src/App.js`'s route
table and the git history since the last dead-ends audit
(`2026-09-14-dead-ends.md`, ~50 commits: HomePreview became the live home page,
business subdomains, per-person demand KPIs, the Smart Lists/price-label

still open (two `Auth.js` one-liners, one dead file, one stale comment, one
missing courier control) — none has regressed further, none has been fixed
either. Two small new issues surfaced: a `/why-list` roadmap item that now
undersells a feature that already shipped, and a banned em-dash that reached
one CTA. The six model fields flagged as "recent suspects" in this cycle's
brief (`faqs`, `kosher_certification`, `delivery_note`, `lead_time`,

not just assumed from a commit message. The admin request-reports moderation

## Dead-end promises: destination lacks the affordance

- **`frontend/src/pages/WhyList.jsx:48-51,164-181` (`en.js:3263-3264`)** —
  the roadmap section (explicitly reserved for "NOT shipped" features, per the
  file's own header comment) lists `dashboardTitle: 'Leads and views
  dashboard'` / `dashboardBody: 'See how many people viewed your listing and
  got in touch. Being built now.'` But the feature is live:
  `frontend/src/components/dashboard/PerformancePanel.jsx` ("How your
  listings are doing" — visitors + taps, per-listing, shipped 18 Sep 2026) is
  wired into both `MyGigsTab.jsx:517` and `PropertyList.jsx:431` — every
  provider and every owner already sees it in their real dashboard. **This is
  the inverse of the usual dead end**: not a broken link, but a sales page
  telling a prospective provider that a shipped feature "isn't available
  yet," undermining the one page whose job is to sell the product. `WhyList.jsx`
  has had no commits since the demand/leads work landed, so the copy was
  simply never updated. **Fix:** move the `dashboard` roadmap key into the
  page's `BENEFITS` list with copy describing what it actually does (per-listing
  visitors + taps, a 14-day chart), or delete it from the roadmap. The
  page's other roadmap item (`verifiedTitle`/`verifiedBody`, "identity and
  credential check") is still accurate — the only "verified" capability that
  exists is an admin-only boolean flag, not a credential-check flow — leave
  that one as-is.

## Wrong destination

- **`frontend/src/pages/Auth.js:114-117`** *(carried over from 09-14, still
  unfixed)* — every other branch of the post-auth redirect calls
  `navigate(destination)` (`postAuthDestination(user)`, which honors
  `?redirect=`), but the `mode === 'signup' && formData.role === 'provider'`
  branch hardcodes `navigate('/businesses/add')`. A provider who signs up via
  a deep link (e.g. `?redirect=/services/post-job`) is silently sent to
  `/businesses/add` instead — the query param is dropped for this one role on
  this one screen. `SignupJoin.jsx` gets the equivalent case right at line
  211. **Fix:** one-line change to `navigate(destination)`, matching the
  pattern three lines below and in `SignupJoin.jsx`.
- **`frontend/src/pages/Auth.js:621`** *(carried over from 09-14, still
  unfixed)* — `<a href="/terms" target="_blank">` has no `rel="noreferrer"`.
  The equivalent Terms link in `SignupJoin.jsx:670` has it. The destination
  itself (`Terms.jsx`) is fine — confirmed real bilingual content, not a stub.
  **Fix:** add `rel="noreferrer"` to match.

## Copy / brand-rule violation (found during the backward pass, not a dead end but worth flagging)

- **`frontend/src/locales/en.js:744`** — `ctaBand: 'Have something to offer?
  Add your business — free.'` uses the banned long dash. CLAUDE.md (ruling
  16 Sep 2026): the standing supply-side CTA is *"Add your business, free"*
  with a comma, "the long dash is banned by the copy rules in
  `brand/voice.md`." The call site
  (`frontend/src/pages/WhatYouCanDo.jsx:131`) actually passes the *correct*
  comma version as a fallback, but because the `en.js` key exists, i18next
  serves the em-dash version instead — the fallback never fires. The
  homepage's own copy of this CTA (`en.js:1523,3866,3868,3933`) is correct.
  **Fix:** edit the `en.js:744` string to match.

## Orphaned capabilities

**Confirmed still open (carried over from 09-14, re-verified today, no fix

  (`backend/routes/marketplace/requests.py:197,205`) — `PostRequest.jsx` has

  `BulkEditModal.jsx`; confirmed absent from both `AddPropertyModal.jsx` and

  `GET /admin/marketplace/summary`, `GET /properties/featured`,
