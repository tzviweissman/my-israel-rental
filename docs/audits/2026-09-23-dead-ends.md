## Dead-end promises: destination lacks the affordance

1. **Google Reviews "Connect" — the `cancelled` outcome is silently dropped.**
   `frontend/src/components/dashboard/GoogleReviewsCard.jsx:47-55` reads the
   `google_reviews` query param back from the OAuth round trip and branches only on
   `connected`/`failed`. The backend (`backend/routes/reviews.py:271`, `google_callback`)
   also sends `google_reviews=cancelled` when the user denies Google consent or the
   token exchange errors. In that case the frontend deletes the param and moves on with
   **no toast at all** — someone who backs out of the Google consent screen gets zero
   feedback that their "Connect Google reviews" click did nothing.
   **Fix:** build the affordance — add an `else if (r === 'cancelled') toast(...)`
   branch alongside the existing two. One line; not a promise worth removing.

*Minor note, not counted as a dead end:* the setup checklist's `prop.photos` /
`prop.availability` items link to `/dashboard?tab=properties` rather than a specific
`?edit=<id>` the way the pricing-quarantine and availability-expiry emails do. The
checklist's own "done" check is `any_of(...)` across all of an owner's properties, so
there's genuinely no single listing to deep-link to when it's unmet — the field and
control are present and reachable, just less direct on an owner with many listings.

## Orphaned capabilities

### New this round

1. **`AutoAcceptEntry.land_in_status` — only `"preparing"` can ever be set.**
   `backend/routes/marketplace/automations.py:222,366` (`Literal["preparing", "ready"]`).
   `frontend/src/components/dashboard/AutomationsPanel.jsx:285,604-640` hardcodes
   `'preparing'` and offers no control for `'ready'`. A courier business that wants
   auto-accepted orders to land straight in Ready cannot get that.
   **Fix:** add a select next to the cap inputs, or drop the enum's second value if
   "Preparing" is the only sane default.

2. **`connections.RelationshipIn` / `PATCH /marketplace/connections/{conn_id}` has no
   caller — the relationship badge can never actually render.**
   `backend/routes/marketplace/connections.py:373-381`. The "Supplier / Customer /
   Courier / Partner" badge is displayed in
   `frontend/src/components/dashboard/NetworkTab.jsx:151-156`, but both places that
   create a connection (`NetworkTab.jsx:330`, `ConnectButton.jsx:84`) omit
   `relationship` from the request, and nothing calls the `PATCH` endpoint that could
   set it after the fact. The badge reads a field no UI path can ever write.
   **Fix:** add a relationship picker to the connect dialog and/or an edit control on
   each partner card, or remove the dead badge and the field/endpoint if descoped.

3. **`GET /marketplace/businesses/{id}/connections?status=declined|disconnected` is
   unreachable.** `backend/routes/marketplace/connections.py:184-217` accepts it;
   `NetworkTab.jsx:96` never sends it — a business can never see a past decline or
   disconnect. Minor.
   **Fix:** add a "History" view to `NetworkTab.jsx`, or drop the param.

4. **Review edits lose their per-category ratings.** `backend/utils/reviews.py:308`
   (`edit_native`) and `PATCH /reviews/{review_id}` accept `sub_ratings`, but
   `EditForm` in `frontend/src/components/reviews/ReviewsSection.jsx:184-198` only
   edits `rating` and `text` — no UI for the five sub-ratings set at review time.
   Verified reviews is new and off-by-default, so nobody has hit this yet.
   **Fix:** add the five `StarInput`s to `EditForm`, mirroring `WriteReview.jsx`.

5. **`GET /admin/auto-owner-nudge/status` and `POST .../run-now` have no frontend
   caller, despite the endpoint's own docstring promising one.**
   `backend/routes/admin/chats_nudge.py:525-545` — the docstring says this is "so the
   admin Chats tab can render a 'auto-nudges on · 12h threshold' strip with counts";
   no such strip exists anywhere in `frontend/src`. Not new code (last touched
   2026-09-02) but missed by the three prior dead-ends audits — the background loop
   runs and logs, but nothing ever surfaces the log or the run-now escape hatch.
   **Fix:** build the strip in the admin Chats tab (backend is complete), or delete
   the promise from the docstring.
