## Broken: goes nowhere or errors

1. **Admin "Verified" toggle calls a route that does not exist** *(re-checked)*.
   `frontend/src/components/admin/ServicesTab.jsx:92` sends `PATCH ${API}/businesses/{id}/verified`. The route is `PATCH /marketplace/businesses/{id}/verified` (`backend/routes/marketplace/businesses.py:965`, router prefix `/marketplace`). Nothing else serves the unprefixed path, so it is a 404 (not confirmed at runtime). Introduced in `1dbbca5`.
   **Fix (correct the call):** use `${API}/marketplace/businesses/...`.

2. **Two emails have a relative "Open" button** *(re-checked)*. `om._email(..., button=(label, href))` puts `href` straight into the anchor (`backend/utils/email.py:263`). These pass the in-app `action_url`:
   - `backend/routes/marketplace/automations.py:563-564`, "Open" -> `/dashboard?tab=orders` etc. (the "notify me" automation email).
   - `backend/routes/marketplace/price_watch.py:116`, "Open" -> `/dashboard?tab=network&view=automations` or `/services/gig/{id}`.
   In a mail client these resolve to nothing. `orders.py` already prefixes `_frontend_url()` correctly.
   **Fix:** prefix the frontend URL in the email call only; keep the relative value for the bell.

## Dead-end promises: destination lacks the affordance

3. **"Add your business" sends people to an empty pane** *(re-checked, `Dashboard.js:532`)*. `?tab=my-businesses`, `orders`, `job-requests` render only when `showGigTabs` is true; `subleases`, `contracts`, `properties`, `bulk-manager` need a role. `ALL_TAB_IDS` accepts every id for everyone and there is no fallback, so for a visitor who does not qualify the content area is blank with no message.
