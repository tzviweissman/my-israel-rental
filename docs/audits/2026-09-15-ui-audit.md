## Should fix

### 1. The moving row keeps its feather mask after it becomes a row you scroll yourself, so the first and last cards can never be fully seen

`frontend/src/styles/home-v2.css:592-596` and the new block at `:622-627`

```css
.hv2-marquee {
  overflow: hidden; margin-top: 26px;
  -webkit-mask-image: linear-gradient(to right, transparent, #000 6%, #000 94%, transparent);
  mask-image: linear-gradient(to right, transparent, #000 6%, #000 94%, transparent);
}
...
@media (prefers-reduced-motion: reduce), (hover: none) {
  .hv2-marquee { overflow-x: auto; scroll-snap-type: x proximity; }
  ...
}
```

The 6% feather at each end is correct for a marquee: cards enter and leave
instead of being guillotined. The new media query turns the same element into a
list the user scrolls, and the mask is not cancelled. On a phone (`hover: none`
matches) and on any desktop with reduced motion, scrolling to the start still
leaves the leading card fading to transparent at the container edge, and the
same at the end. The content the user has deliberately scrolled to is the
content the mask hides. This is a regression from the 09-14 fix, not a
pre-existing issue: before that commit the element was never scrollable.

**Exact fix:** cancel the mask in the same block.

```css
@media (prefers-reduced-motion: reduce), (hover: none) {
  .hv2-marquee {
    overflow-x: auto; scroll-snap-type: x proximity;
    -webkit-mask-image: none; mask-image: none;
  }
  ...
}
```

**Not rendered.** This follows from the two rules above; it was not measured in
a browser. Confirm at 375 by scrolling the row fully to its start and checking
the first card's left edge.

### 2. Pressing "Try again" deletes the whole section, including the live region, for up to 31 seconds

`frontend/src/pages/HomePreview.jsx:321` and `:512`, with
`frontend/src/components/home/useHomeShowcase.js:90`, `:136-139`

```jsx
{loaded && shelf.length === 0 && shelfFailed && !retrying && (
```

```js
const RETRY_DELAYS_MS = [3000, 8000, 20000];
const retry = useCallback(() => { setRetrying(true); setRound((r) => r + 1); }, []);
```

`retry()` sets `retrying` true in the same tick as the click, and both branches
are gated on `!retrying`. So the message, the `role="status"` wrapper and the
button the user just pressed all unmount, and nothing renders in their place.
The next round runs four attempts at 0 s, 3 s, 11 s and 31 s before `retrying`
goes false again, so the section is a blank gap for **up to 31 seconds** after a
deliberate click. A person who clicks and sees the section vanish has been told
their click broke something.

The same gating causes a second, separate failure: `role="status"` at `:324`
and `:513` is a live region that is **inserted already containing its text**.
Live regions announce mutations made after the region exists; a region that
arrives populated is not announced by most screen readers. So the error is
currently silent to assistive tech in every case, not only during a retry.

**Exact fix, which solves both:** mount the region unconditionally and change
only what is inside it.

```jsx
<div className="hv2-picks-head" data-testid="home-preview-picks-error" role="status">
  {loaded && shelfFailed && (
    <>
      <h2>{t('home.v2.picks.h2Deals', "Today's deals")}</h2>
      <p>{t('home.v2.picks.loadError', "We couldn't load today's offers just now.")}</p>
      <button type="button" className="btn btn-ghost hv2-retry" onClick={retry}
              disabled={retrying} data-testid="home-preview-picks-retry">
        {retrying ? t('home.v2.retrying', 'Trying again...') : t('home.v2.retry', 'Try again')}
      </button>
    </>
  )}
</div>
```

`home.v2.retrying` is a new key and needs a line in `he.js` as well as `en.js`.
Apply the same shape to the rentals block at `:512-524`.

### 3. In Smart Lists, every row past the send cap is dimmed below the contrast floor

`frontend/src/components/admin/SmartListsTab.jsx:750`, `:769`, `:782`

```jsx
<li className={`py-4 flex items-start gap-3 ${isSelected ? '' : 'opacity-70'}`}>
```

A fresh generate pre-selects the first `sendCap` rows (`:110-119`, default cap
10 at `:87`), so on any result set larger than ten, **every row from the
eleventh down renders at 70% opacity** - and those are exactly the rows the
admin is reading in order to decide what to swap in.

`opacity` on the `<li>` composites the text against the white panel.

- `:782` `text-gray-500` `#6B7280` at 70% on `#FFFFFF` composites to `#979CA6`.
  Relative luminance 0.331, contrast **2.76:1**. Text is 14px, so the floor is
  4.5:1.
- `:769` `text-gray-600` `#4B5563` at 70% composites to `#818892`. Relative
  luminance 0.244, contrast **3.58:1**. Also 14px, also under 4.5:1.

**Computed, not measured** - arithmetic from the Tailwind palette values and
the WCAG relative-luminance formula, since no browser was available.

**Exact fix:** carry the unselected state on the checkbox and a border, not on
the text. Replace `opacity-70` on the `<li>` with nothing, and mark the
selected row instead:

```jsx
className={`py-4 flex items-start gap-3 ps-3 border-s-2 ${
  isSelected ? 'border-[var(--brand-primary)]' : 'border-transparent'}`}
```

If a dimmed treatment is wanted, apply `opacity-70` only to the row's *image or
icon*, never to its text.

### 4. The Smart Lists row checkbox is a 16px target, has no label, and every checkbox on a filtered list shares one accessible name

`frontend/src/components/admin/SmartListsTab.jsx:753-763`

```jsx
<input type="checkbox" checked={isSelected} disabled={blocked}
  onChange={() => toggleOne(p.id)}
  className="mt-1 w-4 h-4 shrink-0 accent-[var(--brand-primary)] cursor-pointer ..."
  aria-label={t('sweep.includeInMessage', 'Include {{area}} in the message', { area: displayArea })}
/>
```

Three problems in one control:

- `w-4 h-4` is **16x16 CSS px**. WCAG 2.2 Target Size (Minimum), 2.5.8, sets
  24px; this repo's own audit rule sets 44. Nothing enlarges it.
- No `<label>` wraps the row and there is no `htmlFor`, so the area, price and
  beds text beside it is not a click target. The 16px box is the only way in.
- `displayArea` is `appliedFilters?.location || p.area` (`:739`). Filtering by
  Jerusalem gives **every row on screen the identical accessible name**,
  "Include Jerusalem in the message". A screen reader user hears the same
  sentence N times and cannot tell which listing they are ticking.

**Exact fix:** make the row the label, pad the hit area rather than the box, and
name it with something that differs per row.

```jsx
<label className="py-4 flex items-start gap-3 cursor-pointer" data-testid={`smart-list-row-${p.id}`}>
  <input type="checkbox" checked={isSelected} disabled={blocked}
    onChange={() => toggleOne(p.id)}
    className="mt-1 w-4 h-4 shrink-0 p-2 -m-2 accent-[var(--brand-primary)] ..."
    aria-label={t('sweep.includeListing', 'Include {{area}}, {{price}} in the message',
      { area: displayArea, price: formatPrice(p.price, p.currency) })}
  />
```

The `p-2 -m-2` gives a 32px hit box without moving anything; pair it with
`py-4` on the label for a 40px+ row target. Add `sweep.includeListing` to both
locale files.

### 5. The moving row's accessible name is on a bare `<div>`, where ARIA discards it

`frontend/src/pages/HomePreview.jsx:463-468`

```jsx
<div ref={marqueeRef} className="hv2-marquee reveal"
     data-testid="home-preview-recent"
     aria-label={t('home.v2.rentals.h2', 'Recently added')}>
```

A `div` with no role maps to `generic`, and ARIA 1.2 prohibits an accessible
name on `generic`: browsers do not expose this label, so the row is unnamed.
It matters more now than it did yesterday, because `home-v2.css:622-624` turns
this same element into a horizontally scrollable region under reduced motion and
on touch. A scroll container that a keyboard can reach only by tabbing through
its children, with no name, is the case WCAG 2.1.1 is about.

**Exact fix:**

```jsx
<div ref={marqueeRef} className="hv2-marquee reveal" role="group" tabIndex={0}
     data-testid="home-preview-recent"
     aria-label={t('home.v2.rentals.h2', 'Recently added')}>
```

`role="group"` restores the name. `tabIndex={0}` makes the scroll container
reachable, and it composes with the existing
`.hv2-marquee:focus-within .hv2-marquee-track { animation-play-state: paused }`
at `:610-611`: focusing the container now also stops the row, which is the pause
control WCAG 2.2.2 wants and the row still lacks on a pointer device.

## Improvement of the night

**Mechanism: social proof, in its specific-and-countable form.** Social proof
moves behaviour when it is a real number attached to a real population; an
unquantified brand claim does not, because there is nothing for the reader to
compare themselves to. This is the same reason the site already shows review
*counts* rather than star averages: a count is the denominator that makes the
claim interpretable. Not previously proposed - the ten prior audits have used
halo effect, peak-end, loss aversion, denominator neglect, endowed progress,
cognitive fluency, ambiguity aversion, automation bias, position bias, banner
blindness and implementation intentions. Social proof is new.

**Surface:** the attribution band on the business page,
`frontend/src/pages/BusinessPage.jsx:611-642`, which as of `dde2dfa` is what a
first-time visitor to `<slug>.myisraelrental.com` sees at the end of the page.

**What is wrong now:** the file's own comment at `:600-610` is right about the
stakes - *"every one of those people meets MyIsraelRental here for the first
time"* - and then the band makes a bare assertion: a logo, "This page is on
MyIsraelRental", and "List your business - free". The visitor has just been
convinced of the *business* by the owner who sent them the link. What they have
no evidence for is the *host*. A sentence that only names itself gives them
none, and a business owner reading a competitor's page (the audience `:559-564`
is explicitly targeting) is exactly the reader who will not act on an
unquantified claim.

**What to change:** give the band one real, queried count, using the pattern
`FinaleStats.jsx` already established and enforces - number from the database at
runtime, a floor below which the clause hides, and the clause absent rather than
estimated when the number is unavailable.

- Backend: add a business count to the existing trust endpoint
  (`GET /api/properties/stats/trust`, consumed at `FinaleStats.jsx:34`), as
  `count_documents` over published `marketplace_gigs`. No new endpoint, no new
  round trip for the pages that already call it.
- Frontend: in the attribution band, replace the static line with
  `t('businessPage.hostedOnN', 'One of {{n}} business pages on MyIsraelRental', { n })`
  when `n >= FLOOR`, and fall back to the current
  `businessPage.hostedOn` string when it is below the floor or the request
  failed. Set the floor the way `MIN_LISTINGS = 25` was set: a number that
  argues *for* the site. Both keys need `he.js` lines.

**What to expect if it works:** a higher click-through on
`data-testid="business-attribution-cta"` than the current band gets, measured on
subdomain traffic specifically, where the visitor genuinely does not know the
host. The `data-testid` already exists, so the before/after is comparable
without new instrumentation.

**What would falsify it:** if CTR does not move, these visitors are not
evaluating the host at all - they came for the business and left with it - and
the right response is to make the band *smaller*, not to add more to it.

**Honesty check:** the number is a `count_documents` result or the line does not
render. No scarcity, no countdown, no invented figure, and no change to the
positioning (rentals still lead everywhere this page does not; the supply CTA
stays "free").
