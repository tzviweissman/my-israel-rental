## Blockers

### 1. The sphere's 36 nodes are keyboard-focusable and unmount while focused

`frontend/src/components/ui/img-sphere.jsx:199-236`

Every visible node renders as `<div role="link" tabIndex={0}>` (`:218-219`).
`SignupSphere` asks for `WANT = 36` images (`SignupSphere.jsx:28`) and passes
`onOpen`, so every one of them is a tab stop, placed after the sign-up form's
submit button.

Two things go wrong, and the second is the blocker:

1. A node behind the equator returns `null` (`:201`, `n.hidden` when `z < -0.15`).
   `autoRotate` runs at `autoRotateSpeed={0.18}` degrees per frame, roughly
   10.8°/s, so nodes cross that threshold continuously. **A keyboard user who
   tabs onto a node has it unmounted under them within a few seconds**, and
   focus falls back to `<body>` - losing their place in the form they were
   filling in.
2. There is no visible focus indicator. `App.css:548-554` scopes the
   `:focus-visible` ring to `input, textarea, select, button, [contenteditable]`.
   A `div[role="link"]` matches none of them.

**Fix:** make the sphere a single tab stop, not 36. Put `tabIndex={-1}` on the
nodes, keep the click handler, and give the *container* (`img-sphere.jsx:188-198`)
`tabIndex={0}` with `role="group"` and an `aria-label`, plus arrow-key rotation.
Reachable content already exists elsewhere on the site (the sphere links to
`/property/:id` and `/businesses/:id`, both listed on their own boards), so the
decorative panel does not need to be a link list. If individual links must stay
reachable, stop unmounting them - render hidden nodes with
`visibility: hidden; pointer-events: none` so the element survives the rotation -
and add an explicit focus ring, since the global one will not apply.

## Should fix

### 2. The price filter says ₪ but the backend compares mixed currencies

`frontend/src/pages/RequestsBoard.jsx:585-604` (labels), `:446-447` (send)
with `backend/routes/marketplace/requests.py:554-564`

Both inputs are labelled and placeholdered `Min ₪` / `Max ₪`
(`en.js` `requests.minPrice`/`maxPrice`). The backend filters
`budget_amount` with a raw `$gte`/`$lte` and **never looks at
`budget_currency`**, which `requests.py:182` defines as `ILS | USD` and
`:679` stores per post. The site itself knows the difference -
`requests.py:1210-1212` picks `₪` or `$` from that field when it renders a
budget.

So a buyer filtering "under ₪500" is shown a $500 item (about ₪1,850) and not
shown a ₪600 one. The shekel sign in the label makes a promise the query does
not keep.

**Fix, frontend-only:** drop the currency from the two strings -
`minPrice: 'Min price'` / `maxPrice: 'Max price'` (he: `'מחיר מינימלי'` /
`'מחיר מקסימלי'`) - until the backend converts. The correct long-term fix is
backend: normalise to a `budget_amount_ils` at write time and filter on that,
but that is a schema change and out of scope for a UI report.

### 3. En-dash in a visible string - hard ban

`frontend/src/pages/RequestsBoard.jsx:593`

```jsx
<span className="text-xs" style={{ color: 'var(--brand-muted)' }} aria-hidden="true">–</span>
```

U+2013, rendered on screen between the two price inputs. `taste-skill` §9.F
bans en- and em-dashes in visible strings without exception; `aria-hidden` hides
it from screen readers, not from eyes.

**Fix:** replace the character with a plain hyphen: `>-<`. (Everything else
flagged by a dash grep in these files is inside a `//` or `/* */` comment, which
is fine.)

### 4. Accent-blue links on white measure 3.32:1 at 12px

Computed WCAG contrast for `--brand-primary` `#1C8DD4` (theme-flow.css:51) on
`#FFFFFF`: relative luminance 0.2666, ratio **3.32:1**. The 4.5:1 minimum
applies because both instances are 12px:

- `frontend/src/pages/RequestsBoard.jsx:620-626` - the "Clear" link,
  `text-xs font-semibold underline`, `color: var(--brand-primary)`
- `frontend/src/components/marketplace/FaqEditor.jsx:85-93` - the
  "Add a question" button, `text-xs font-semibold`, `color: var(--brand-primary)`

3.32:1 clears the 3:1 bar for large text only, and neither of these is large
text (large = 18.66px bold or 24px regular).

**Fix:** use `var(--brand-primary-deep)` `#0F5E8F` on both. Measured:
luminance 0.1049, **6.98:1** on white - passes at any size, and it is already
the palette's deep accent, so no new value is introduced.

### 5. New filter controls are 30px tall at 375 - and shorter than the row above them

`frontend/src/pages/RequestsBoard.jsx:565-577` (condition chips),
`:583-604` (price inputs), `:610-616` (the "Show sold" checkbox)

All of the chips and inputs are `px-3 py-1.5 text-xs`: 12px font on Tailwind's
16px `text-xs` line-height, plus 6px padding top and bottom, plus 1px border
each side = **30px**. The 44px minimum is missed by 14px, and the native
checkbox at `:611-615` is smaller still (~13px, UA default).

This also breaks the visual rhythm of the panel: the type tabs directly above
are `.wh-tab` (`App.css:928-936`), `padding: 9px 22px` at `font-size: 14px`, so
about 38px. Two filter rows, stacked, at two different heights.

**Fix:** `py-2.5` on the chips and both inputs (16 + 20 + 2 = 38px, matching
`.wh-tab`), and wrap the checkbox in a `min-h-[44px] py-2.5` label so the whole
label is the target on touch. 38px is a deliberate compromise with the existing
row - if the 44px bar is to be met properly, `.wh-tab` has to move too, which is
a separate change.

## Nits

### 6. The sign-up panel's entrance ignores `prefers-reduced-motion`

`frontend/src/components/auth/SignupSphere.jsx:88-104`

The eyebrow and the blockquote animate in with `y` + `filter: blur(8px)` over
0.7-0.8s, and the sphere wrapper scales in at `:109-113`. None of it is gated.
The sphere's own rotation *is* gated - `img-sphere.jsx:108-109` reads the media
query and `:119` drops the auto-spin - which makes the gap on the entrance
animations look like an oversight rather than a decision. CLAUDE.md ("respect
`prefers-reduced-motion`") applies.

**Fix:** hoist the reduced-motion read into `SignupSphere` and set
`initial={false}` on all three `motion` elements when it is true, e.g.
`const reduced = useReducedMotion()` from `motion/react` (already a dependency,
`package.json:21`), then `initial={reduced ? false : { opacity: 0, y: 12, ... }}`.

### 7. The price inputs desync from the URL on browser Back

`frontend/src/pages/RequestsBoard.jsx:407-408`

```js
const [minDraft, setMinDraft] = useState(minPrice);
const [maxDraft, setMaxDraft] = useState(maxPrice);
```

`useState` reads the URL once, at mount. Every other filter on this board is
derived from `searchParams` on each render and so follows history correctly. The
"Clear" button papers over the common case by calling `setMinDraft('')`
explicitly (`:621`), but a browser Back out of a price filter leaves the old
number sitting in the box while the results show the unfiltered board.

**Fix:** add
`useEffect(() => { setMinDraft(minPrice); setMaxDraft(maxPrice); }, [minPrice, maxPrice]);`
after the declarations, and drop the two `setMinDraft`/`setMaxDraft` calls from
the Clear handler, which the effect then covers.

### 8. FAQ rows are keyed by array index

`frontend/src/components/marketplace/FaqEditor.jsx:49-50` - `key={i}`

Remove row 1 of 3 and React reuses the DOM nodes by position, so row 2's text
appears to slide into row 1's box. With controlled inputs the *values* stay
correct, but caret position, scroll position inside the textarea, and any IME
composition in Hebrew are attached to the reused node and do not follow the
content. Cheap to avoid on a component that is brand new.

**Fix:** give each row a stable id at creation - `add()` at `:38` becomes
`onChange([...rows, { q: '', a: '', _k: crypto.randomUUID() }])` - key on
`row._k ?? i`, and strip `_k` in `cleanFaqs` (`:21-24`) so it is never sent.

## Improvement of the night

**Mechanism: the endowed progress effect.** People complete a task at a
markedly higher rate when it is presented as already begun rather than as not
yet started - the classic demonstration is the loyalty card that needs ten
stamps and arrives with two already punched, which outperforms an eight-stamp
card requiring the same eight purchases. The work required is identical; what
changes is whether the person is starting or continuing.

Not previously proposed: the four earlier audits used the halo effect
(2026-09-01), the peak-end rule (09-02), loss aversion (09-03) and denominator
neglect (09-04-2).

**Surface:** the FAQ editor, on both surfaces that mount it -
`frontend/src/pages/CreateGig.jsx:626-630` (the create wizard, description step)
and `frontend/src/components/dashboard/EditListingModal.jsx:357-359`.
**File to change:** `frontend/src/components/marketplace/FaqEditor.jsx:32-47`
and `:84-94`.

**The situation.** As shipped tonight, a listing with no FAQs renders a title, a
hint paragraph, and one "Add a question" button. Nothing is begun. The provider
must decide to start, click, and only then discover what a row looks like - and
the placeholders, which are the most persuasive part of this component
(`:57` "e.g. How far in advance should I book?", `:68` "e.g. A week is plenty.
Same-day is sometimes possible, message me."), are invisible until after that
decision. The provider is asked to commit before being shown what they are
committing to.

**What to change.** When `rows.length === 0`, render one empty row rather than
none - the fields open, the placeholders visible, nothing typed. Keep the
"Add another question" button below it. The safety net already exists and needs
no change: `cleanFaqs` (`:21-24`) drops any row missing either half, so a
provider who ignores the open row sends exactly what they send today. Concretely:
in `FaqEditor`, replace `const rows = Array.isArray(faqs) ? faqs : []` at `:34`
with a version that substitutes `[{ q: '', a: '' }]` when the array is empty, and
have `setRow` call `onChange` with that seeded array so the first keystroke
commits it. This is display-only seeding - do not write the empty row into
`form.faqs` on mount, or `EditListingModal`'s dirty check at `:199-200` will see
a change where the provider made none.

Two constraints this respects: nothing is pre-filled with invented content (the
placeholders are examples, prefixed "e.g.", and never submitted), and the row is
freely ignorable - no confirmshaming, no blocking, no required field.

**What I would expect to see if it worked.** The share of newly published
listings carrying at least one FAQ rises. Today that number is effectively zero
by construction - the dead-ends audit of 2026-09-03 (#9) found that the only way
a listing ever got an FAQ was the demo seed script, so any post-change figure
against listings created before tonight is a clean comparison. The secondary
signal is a fall in first-contact chat messages asking what the FAQ placeholders
name - lead time and what is included - on listings that filled one in. Both are
countable from existing data; neither requires a new event.

## Resolution (5 September 2026)

All eight findings and the improvement are fixed.

**A correction to this report's header.** The work was not uncommitted: it
went in as `f19dac7` and `76fe5d5` and was pushed to `main` before this
audit ran. The scope it derived from the working tree was right, and every
finding held.

- **1 (blocker).** The sphere is one tab stop. The nodes are
  `aria-hidden` and not tabbable; the container takes the focus, carries
  `role="group"` and a name, draws its own ring (the global rule reaches
  form elements only), and arrow keys turn it - Shift for a bigger step.
  Nothing unmounts under a focused element any more, because the focused
  element is the sphere.
- **2.** Fixed in the backend rather than by relabelling. The bounds are
  shekels and each post is matched in its own currency, at the rate the
  services board already uses. A `$or` over the two currencies, so no
  schema change and no backfill.
- **3.** The en-dash between the price inputs is a hyphen.
- **4.** Both 12px accent links use `--brand-primary-deep`. Measured on
  white: the accent is 3.61:1 (this report says 3.32; either way it is
  under 4.5), the deep is 6.96:1.
- **5.** Chips and price inputs are `py-2.5`, so 38px, matching the tab
  row above. The sold toggle's whole label is a 44px target.
- **6.** `useReducedMotion` gates all three entrance animations.
- **7.** An effect syncs the price drafts from the URL, so Back reaches
  the boxes. The Clear handler no longer sets them by hand.
- **8.** Rows carry a stable `_k`, created with the row and never sent.
- **Improvement.** The editor opens with one empty row. Display-only: it
  is never written into the caller's state on mount, so the edit sheet's
  "nothing changed" check is untouched, and `cleanFaqs` drops it if it is
  left alone.
