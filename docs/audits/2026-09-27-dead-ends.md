## Wrong destination

- **`frontend/src/components/Navigation.js:37`** —
  `const isPreview = location.pathname === '/home-preview';` gates the
  flow-pill nav treatment (used at line 440) that was built for the
  redesigned home page. It has been unchanged since 15 Sep (`a06f242`),
  written *before* that redesign went live. `App.js:401-406` now says in its
  own comment: *"The redesigned page became the home page on 19 Sep 2026
  (Tzvi). `/home-preview` renders the same page as the lab, where palette
  experiments are scoped."* Since the redesign moved to `/` on 19 Sep and
  `/home-preview` became the leftover lab-only alias, this line has it
  backwards: **the live homepage at `/` renders the plain nav, and the
  noindex'd lab alias `/home-preview` gets the intended flow-pill nav.**
  Every link in the nav still resolves correctly regardless of which pill
  style renders, so this is a visual/component-selection bug, not a broken
  destination — reported here because it sits exactly where the audit was
  told to look hardest, and because the stale comment two lines above it
  ("everything it tries stays there until Tzvi moves it") is now factually
  wrong: it has moved. **Fix:** change line 37 to `location.pathname === '/'
  || location.pathname === '/home-preview'`, or drop the distinction now
  that both routes render the same component.

## Orphaned capabilities

**New this cycle:**

- **`Connection.relationship`** (`backend/routes/marketplace/connections.py`,
  `Literal["supplier","customer","courier","partner"]`) has a working reader
  but no writer. `NetworkTab.jsx:144,151-155` displays it via `relLabel()`,
  but the connect flow (`ConnectButton.jsx:84`, `NetworkTab.jsx:330`) POSTs
  only `target_business_id`/`note` — never `relationship`. `PATCH
  /marketplace/connections/{conn_id}` (`set_relationship`, `connections.py:374-378`)
  has zero callers anywhere in `frontend/src`. The label column exists and
  the field is modeled end-to-end server-side, but nothing in the UI can
  ever set it to anything other than null. **Fix:** either add a
  relationship picker to the connect/accept flow (build the affordance), or
  if this was scaffolding for a feature not yet designed, drop the display
  column until it can be set — showing an always-blank label is its own
  small dead end.

**Carried over from 09-14, still open** (re-verified this run via git log +
current grep, no regression, no fix landed):

  never sets either.

- `checkin_time`/`checkout_time` — still only reachable via `BulkEditModal.jsx`,
