# Dead ends - 2026-10-01

Scheduled dead-ends audit following `.claude/skills/dead-ends/SKILL.md`. Three
parallel static passes (forward, backward, orphaned capabilities) against
`App.js`, backend guards and the 123 commits since the 09-14 audit. Baseline:
`2026-09-14-dead-ends.md`.

**Headline:** every 09-14 item with real user impact is fixed (admin
request-reports UI, courier leave, `GigPatch.status paused`, Auth.js redirect
and `rel`, `BlocksHero`). New this run: one payment-adjacent guard bounce, one
API-rejected booking path, and several "go to settings" promises whose
destination lacks the control. All findings are static; nothing was clicked.

## Broken: goes nowhere or errors

1. **`/payment/success` loses the destination** - `frontend/src/App.js:437`
   uses a bare `<Navigate to="/auth/login" />`. PayPal returns here
   (`backend/routes/payments.py:170-171`); if the session was lost in the round
   trip, `?orderId=`/`?token=`/`?flow=` (read at `PaymentSuccess.js:27-29`) are
   dropped. Highest stakes, it follows a payment. **Fix:** use `ToAuth`
   (defined `App.js:74`).
2. **`/chat/:propertyId` loses the destination** - `App.js:435`, same bare
   Navigate. Linked from emails at `backend/utils/email.py:514` (mention) and
   `:591` (new message), both `/chat/{id}?with=`. A signed-out recipient lands
   on the dashboard, not the conversation. **Fix:** use `ToAuth`.
3. **"Send booking request" opens a form the API rejects** -
   `frontend/src/pages/GigDetail.jsx:564, 603-619, 1142-1157`. A non-store gig
   with `booking_mode` `whatsapp` (the model default, `shared.py:633`) and a
   number the frontend deems invalid (e.g. landline) falls through to the
   booking modal; `backend/routes/marketplace/gigs.py:1130-1131` returns 400
   "This gig only accepts WhatsApp bookings". The store and message paths were
   fixed earlier; this one was missed. **Fix (build):** in `handleBookClick`,
   when `booking_mode !== 'in_platform'` and WhatsApp is unusable, call
   `messageOnSite()` and relabel the button "Message".
