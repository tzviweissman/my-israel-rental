# Dead ends - 2026-09-30

Scheduled audit following `.claude/skills/dead-ends/SKILL.md`. Three parallel
static passes (forward, backward, orphaned capabilities) against HEAD `7dfa615`
(123 commits since the 2026-09-14 audit). Findings marked **[confirmed]** were
re-opened by hand by the coordinating session; the rest are from the passes and
are static-analysis only. No browser run (see Not checked).

**Headline: one admin control is broken today (verified toggle 404s), one
checklist item can never tick, and a role-gated dashboard tab gives
business-owning non-providers a blank pane.** Most of the 09-14 list is fixed.

## Broken: goes nowhere or errors

1. **Admin "verified" toggle 404s [confirmed].**
   `frontend/src/components/admin/ServicesTab.jsx:92` calls
   `PATCH ${API}/businesses/{id}/verified`. The route is
   `backend/routes/marketplace/businesses.py:965` under router prefix
   `/marketplace`, so the real path is `/api/marketplace/businesses/{id}/verified`.
   No other router mounts `/businesses/.../verified`. The catch block swallows
   the failure. **Fix (build): add `/marketplace` to the URL.** One line.

2. **`/chat/:propertyId` guard drops the return path [confirmed at App.js:435].**
   `user ? <Chat /> : <Navigate to="/auth/login" />`, a bare Navigate rather
   than `ToAuth` (App.js:74). Emailed "Reply"/"View conversation" links
   (`backend/utils/email.py:514,591`, `routes/admin/chats_nudge.py:370`) send a
   logged-out recipient to login, then to the dashboard, not the conversation;
   `?with=` / `?sublease_id=` are lost. **Fix: `<ToAuth />`.**

3. **`/payment/success` guard drops the return path [confirmed at App.js:437].**
   Same bare Navigate. PayPal returns (`routes/payments.py:170`,
   `marketplace/subscription.py:276`) carry `token`/`orderId`/`flow`, read by
   `PaymentSuccess.js:26-29`. If the session is gone on return, the params are
   discarded and the capture/activation never runs, so the user is never told
   whether they paid. **Fix: `<ToAuth />`.**

## Dead-end promises: destination lacks the affordance

4. **Network tab "Add your business" for non-provider owners [confirmed gate].**
   Prompt: "Add your business, free, to connect with other businesses."
   (`NetworkTab.jsx:131-136`, `network-no-business`). Button goes to
   `/dashboard?tab=my-businesses`. `Dashboard.js:532` renders that pane only when
   `showGigTabs` (`canPublishGigs(user) || gigs_count > 0`, line 58); an owner or
   manager with no gigs gets a blank pane, no error. The host tour step
   `h.automations` (`tourSteps.js:54-55`) lands on the same button. **Fix
   (build):** for users who cannot publish gigs, point the button at
   `/businesses/add` (route exists, App.js:504). Also matches the CLAUDE.md
   positioning (the site is not owner-only).

5. **Checklist "Set your availability" never ticks for iCal users [confirmed].**
   `setup.item.prop_availability` (`locales/en.js:1267`), links to
   `?tab=properties`. `backend/routes/onboarding.py:202,231` test
   `available_from or ical_url` (singular), but `routes/ical.py:34-37` writes only
   `ical_urls`. A host who connects a calendar, as the tour tells them to, keeps
   the row open. **Fix (build):** test non-empty `ical_urls` in both the
   projection and the check; drop `PropertyCreate.ical_url` (`models.py:135`).

6. **Business checklist for business-owning non-providers (conditional,
   unconfirmed).** `onboarding.py:179` (`wants_business = role == "provider" or
   has_business`); every `biz.*` href is `?tab=my-businesses...`, same gate as #4.
   Only bites a business with zero gigs; not confirmed whether `/businesses/add`
   always creates a gig. **Fix:** make the tab gate and the checklist use one
   predicate (`useDashboardNav.js:41-44` already says they should).
