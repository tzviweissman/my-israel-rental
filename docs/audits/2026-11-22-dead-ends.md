## New findings

### Dead-end promises (the destination lacks what was promised)

1. **[Low] Discount codes: "Show it at checkout for customers to pick" works on one checkout of four**
   - Control: the tick box `code-show`, label "Show it at checkout for customers to pick" (`discounts.showAtCheckout`), on every percent or amount code, whatever "Works on" is set to (`frontend/src/components/dashboard/DiscountsTab.jsx:69`). Added 22 Nov (2c03fb48).
   - What is there:
     - The list of codes to pick comes from `GET /marketplace/gigs/{id}/promo`, which leaves out every "Memberships only" code (`backend/routes/marketplace/discounts.py:363-364`). A memberships-only code with the box ticked is shown nowhere.
     - Only the shop order page passes those codes to the code box (`OrderPage.jsx:634`, `offers=`). The membership sign-up (`MembershipSignupPage.jsx:144`), a service booking on a listing (`GigDetail.jsx:323`) and paying a quote (`QuoteTrackPage.jsx:87`) use the same code box with no `offers`, so they show only "Have a discount code?".
   - Proof: as the dev owner on the local site, made a business with a shop listing and a monthly membership, then two codes with the box ticked: `BOTH74068` (10%, orders and memberships) and `MEMB74068` (15%, memberships only). `GET /promo` for the shop returned `["BOTH74068"]` only. On the membership sign-up page (phone): `discount-open` 1, `discount-offers` 0, neither code listed. Screenshot `docs/audits/shots/2026-11-22/membership-signup-no-shown-codes.png`. The service booking and quote pages were read in code only (the test data has no bookable package or quote).
   - Fix (Tzvi's choice): build: a `GET /marketplace/businesses/{id}/promo` (or a `form` parameter) that includes membership codes, and pass `offers` on the three other checkouts; or change the promise: label the box "Show it on my order page" and hide it when "Works on" is "Memberships only".

No broken links found: every literal link and `navigate()` target resolves (below).
