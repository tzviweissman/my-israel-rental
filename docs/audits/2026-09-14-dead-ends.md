## Wrong destination

- **`frontend/src/pages/Auth.js:113-118`** — in the
  `mode === 'signup' && formData.role === 'provider'` branch, the redirect
  target is hardcoded to `navigate('/businesses/add')` instead of
  `navigate(destination)` (the variable every other branch in the same
  function uses, line 118). An explicit `?redirect=` on this URL is silently
  dropped, but only for provider signups. **Why low severity:** `grep` for
  `/auth/signup` across the frontend returns zero hits — no in-app control
  ever links here; every real signup entry point uses `/signup` or `/join`
  (`SignupJoin.jsx`), which gets this right (`SignupJoin.jsx:211`,
  `navigate(redirectParam || '/businesses/add')`). Only reachable via a
  hand-typed or externally-bookmarked URL today. **Fix:** one-line change,
  `navigate('/businesses/add')` → `navigate(destination)`, to match the
  pattern already used three lines below it and in `SignupJoin.jsx`.

- **`frontend/src/pages/Auth.js:621`** — `<a href="/terms" target="_blank">`
  has no `rel` attribute. Same-origin target, so the practical risk (a
  malicious page controlling `window.opener`) doesn't apply here, but it's
  the one inconsistent case out of every `target="_blank"` anchor in the
  frontend — the equivalent Terms link in `SignupJoin.jsx:670` correctly
  carries `rel="noreferrer"`. **Fix:** add `rel="noreferrer"` to match.

## Orphaned capabilities

**New since 09-08:**

- **`WebsiteOrderIn.pay_by`** (`backend/routes/marketplace/orders.py:1800`,
  read at 1947-1969 to append "Pays by: X" to order notes) has no frontend
  setter. `OrderPage.jsx`'s POST body (lines 143-150) never includes it —
  there's no payment-method selector on the public order form, only a static
  `payNote` display. Part of the recent order-notes feature
  (`263dc99`); the "how they intend to pay" half of that feature isn't
  reachable by the customer filling the form. Minor (optional field), but
  dead capacity in code that shipped this cycle.
- **`POST /marketplace/courier/businesses/{business_id}/leave`**
  (`orders.py:1290`) is called server-side by `decline_invite` for declining
  a *pending* invite (wired via `DeliveriesTab.jsx:61`), but there's no UI
  path for a courier who has already **accepted** to later leave an active
  business — `DeliveriesTab.jsx` only renders accept/decline for pending
  invites (lines 58-70, 88-90). A courier can join a business's delivery
  roster but has no self-service way to stop; only the business owner can
  remove them. **Fix:** add a "stop delivering for this business" control to
  the active-business list in `DeliveriesTab.jsx` calling the existing
  endpoint — the backend capability is already correct, only the affordance
  is missing.
- **`frontend/src/components/home/BlocksHero.jsx`** — dead code, not
  imported anywhere. An earlier glass-block hero iteration superseded by
  `LoopHero.jsx` (the one `HomePreview.jsx` actually renders) across the
  string of hero-rewrite commits this week. **Fix:** delete the file.
- **`contractManager.noContracts`/`contractManager.uploadFirst`**
  (`frontend/src/locales/en.js:2455-2458`) — orphaned locale keys, no
  component references either string. Not a user-facing dead end (nobody
  can see it to be misled), just unused copy. **Fix:** delete when next
  touching that locale section, not urgent.
