## Should fix

1. **Contrast: dimension text on the size ladder's accent background computes to ~3.79:1, below the 4.5:1 body-text minimum.**
   `frontend/src/components/pagebuilder/SizeLadderBlock.jsx:164` (mobile "current size" badge) and `:179` (desktop list, the `aria-current` row) both render `<span className="block text-xs opacity-80">{dims(...)}</span>` inside a container styled `background: 'var(--pg-accent)', color: 'var(--pg-accent-on)'` (set at `:161` and `:175`).

   `--pg-accent` defaults to `var(--brand-primary)` (`frontend/src/styles/page-theme.css:53`), which in `theme-flow.css` is `#1C8DD4`. `--pg-accent-on` defaults to `var(--ink)`, `#111827` (`page-theme.css:54`; `theme-flow.css:43`). Ink-on-accent at full opacity is ~4.91:1 (passes), but `opacity-80` composites the ink over the accent background, blending to roughly `#132F4A`. WCAG relative-luminance calc on that blended colour against `#1C8DD4`: L(text) ~0.0267, L(bg) ~0.2404, contrast = (0.2404+0.05)/(0.0267+0.05) ~ **3.79:1**. `text-xs` is well under the 18pt/14pt-bold "large text" threshold, so this needs 4.5:1 and fails.
   Note: `--pg-accent` is set per-business inline (`BlockList.jsx:68`, from `businessAccent.js`), so the real ratio varies by business; 3.79:1 is the default/fallback case, computed from the actual token hex values as above, not measured live.
   **Fix:** drop `opacity-80` on these two spans (use the same full-opacity `--pg-accent-on` as the name line above it), or use a colour on the accent background that clears 4.5:1 at 80% opacity.

## Improvement of the night

**Mechanism: the picture superiority effect** (Nelson, Reed & Walling, 1976; pictures are encoded and later recalled far more reliably than words or numbers alone). Not previously used here (already spent: halo effect, peak-end rule, loss aversion, denominator neglect, endowed progress, cognitive fluency, ambiguity aversion, automation bias, implementation intentions, banner blindness, position bias, social proof, choice overload per the standing index).

**Surface:** the size ladder's desktop size list, `frontend/src/components/pagebuilder/SizeLadderBlock.jsx:171-184` (the `<ol>` of `pg-sizes-item` rows), on the new `sizes` page-builder block shipped this window (`f6db488`).

**What is wrong now:** the block's own docblock (`:1-17`) explains why it was built: on the practice page it replaced, "it showed me how big each board actually is" was the moment that sold the page. The drawn stage (`:129-156`) delivers that: a photo, filled in at the current item's true scale. But the text list beside it, the part a shopper actually reads top to bottom to compare every size and price, drops the photo entirely. Each `<li>` (`:172-182`) renders only a name, a dimension string and a price; `productPhotos(x)` is imported and already used for the single "current" item (`:100`) but never called per row in the list. The one surface built specifically to make size legible by showing it, rather than stating it, reverts to pure text for every row except whichever one the scroll position happens to land on.

**What to change:** give each `pg-sizes-item` a small thumbnail (e.g. 32-40px) from `productPhotos(x)[0]`, the same data already available and already used for the stage image, so a shopper scanning the list gets the photo-to-size association reinforced on every row, not just the current one.

**What I would expect to see if it worked:** a rise in click-through on the ladder's own CTA (`pg-sizes-order`, which routes to `/order/:id` or `/services/gig/:id`) relative to before the change, checkable against the lead/view data this site already records (`backend/utils/view_tracking.py`'s `record_view` / `view_summary`, and `lead_events`) for the businesses carrying a `sizes` block, rather than a new tracking hook.
