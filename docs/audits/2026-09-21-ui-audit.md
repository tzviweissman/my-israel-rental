## Should fix

**1. The "from {business}" chip on the order card is 3.23:1.**
`frontend/src/components/dashboard/OrderCard.jsx:96-101` sets
`color: var(--brand-primary)` (`#1C8DD4`, theme-flow.css:51) on
`rgb(var(--brand-primary-rgb) / 0.10)` over the white card. The composite background is
`#E8F4FB`; the ratio, computed from sRGB, is **3.23:1** for 10px semibold text
(needs 4.5:1). The same pair on white is the known 3.61:1. The relationship pill in
`NetworkTab.jsx:149-152` (Phase 1, older) is the same pair at 11px.
*Fix:* `color: 'var(--brand-primary-deep)'` (`#0F5E8F`, theme-flow.css:53), which is
**6.22:1** on the wash and 6.96:1 on white. Apply to both chips.

**2. "Accepted automatically" exists only as a `title` attribute.**
`OrderCard.jsx:98` - `title={o.automation.auto_accepted ? t('orders.viaAutoTitle', ...) : undefined}`.
The card's own header says it is designed for 375px, one-handed; a phone has no hover, so
the one fact the spec says the owner needs ("why is this order already in Preparing?")
is unreadable on the device the card is built for. `title` is also not announced by most
screen readers on a `<span>`.
*Fix:* render it. Either extend the chip text
(`from Dan's Bakery · accepted automatically`, one middle-dot, allowed) or add a second
`text-[10px]` chip beside it using the existing `orders.viaAutoTitle` key, which is
already in both locales.

**3. The rule summary uses an unmirrored arrow.**
`AutomationsPanel.jsx:203` renders `{triggerLine(rule)} → {t('automations.orderFor', ...)}`.
In Hebrew the sentence reads right-to-left and the arrow points the wrong way
(`כשהזמנה שלי בסטטוס מוכנה → הזמנה עבור דן`). Directional glyphs need mirroring or
replacing (Part A item 6).
*Fix:* replace the glyph with a word in both locales: `t('automations.then', 'then')` /
`'ואז'`, or `isRtl ? '←' : '→'` via `hooks/useIsRtl.js`. The word is the better fix;
it also survives font fallback.

## Improvement of the night

**Mechanism: trust calibration in automation (Lee & See, 2004, "Trust in Automation:
Designing for Appropriate Reliance").** People come to rely on an automated step in
proportion to the performance feedback they can see, and the feedback works when it
appears *where the person acted*, not in a separate log they have to go and open.
Without it, trust does not form; the person keeps doing the task by hand as well
(double-ordering, phoning to check) or switches the rule off. This is distinct from the
automation-bias improvement of 09-08 (Skitka's commission error: over-trusting an aid's
output on a form); this is the opposite failure, under-reliance from missing feedback.
Not one of the twelve mechanisms already used here.

**Surface:** the sender's own order card, `frontend/src/components/dashboard/OrderCard.jsx:113-131`
(the meta row that already shows courier, payment and "delivered 14:02").

**What is missing:** when a bakery marks an order Ready and a rule fires, the courier's
board gets an order with a "from Dan's Bakery" chip and the courier gets a bell
(`automations.py:377-404`). The *bakery* gets nothing on the order it just touched. The
only evidence the rule ran is the run log at the bottom of Network → Automations
(`AutomationsPanel.jsx:366-396`), two tabs away. `_record()` writes the run but
`_create_partner_order()` never writes anything back to `source_order_id`'s document.

**Change:**
1. Backend, in `_create_partner_order` after `:396`: `$push` onto the source order
   `sent_to: { business_id, business_name, order_id, at, auto_accepted }`.
2. `OrderCard.jsx:113-131`: one more line in the existing meta row, per entry, using the
   `Zap` icon already imported: *"sent to Dan's Couriers 14:02"* and, when true,
   *"· accepted automatically"*. Two keys, `orders.sentTo` and `orders.sentToAccepted`,
   in `en.js` and `he.js`. Real record, real name, real time; nothing rendered when the
   array is empty.

**What you would expect to see if it worked:** fewer visits to `?tab=network&view=automations`
per order marked Ready (both are already logged: page views by tab, runs by `event`);
fewer rules toggled `enabled:false` in their first week (`automations` PATCH history);
and fewer manual duplicates, i.e. a `manual.reorder` run or a hand-typed order to the
same partner within minutes of an automated one for the same source order.
