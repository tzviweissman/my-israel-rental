# Dead ends - 2026-09-20

Methodology: `.claude/skills/dead-ends/SKILL.md`. Route table built from
`frontend/src/App.js`; forward pass over every `<Link|to=\{|navigate\(|href=|window.location`
in `frontend/src`; backward pass over checklist/empty-state/toast copy; orphan
sweep over `backend/routes/**` endpoints, model fields, enum values, and
`frontend/src/components/**/*.jsx` imports. No dev server / browser was
available in this sandbox (see "Not checked"), so verification is static
(grep both directions: does the frontend call this endpoint with this param,
does the destination component render this field) rather than click-through.

## Previously-known findings — status

All six background findings from the prior audit are now **fixed**, with
regression comments/tests in place. Verified, not re-reported as new:

1. **"Message on MyIsraelRental" 400** — fixed. `ContactChannels.jsx` +
   `GigDetail.jsx#messageOnSite` (line ~638) now route every gig, including
   stores, to site chat (`/chat/:id?with=...`) instead of the booking
   endpoint; `PropertyDetail.js#handleChat` (line 315) does the same for
   properties. Both confirmed to hit routes that exist and are guarded with
   a proper login redirect.
2. **`_normalize_category` called from nowhere** — fixed.
   `backend/routes/marketplace/gigs.py:174` now calls it before
   `_validate_category`, with `backend/tests/test_legacy_category_slugs.py`
   as a regression test.
3. **`GigPatch.status` accepts `paused`, no UI sets it** — fixed.
   `frontend/src/components/dashboard/MyGigsTab.jsx:402-411` (`setPaused`)
   PATCHes `status: 'paused'|'published'`, with a pause/resume button and
   translated copy in both locales.
4. **Requests API filters (`condition`, `min_price`, `max_price`,
   `include_sold`) unused by the board** — fixed.
   `frontend/src/pages/RequestsBoard.jsx:402-630` reads and writes all four
   as URL query params and sends them on every fetch.
5. **Two admin moderation endpoints (`/admin/request-reports*`) unused** —
   fixed. `frontend/src/components/admin/RequestReportsTab.jsx` calls both
   and is mounted at `AdminDashboard.js:199` (`activeTab === 'requests'`).
6. **Jobs digest promised, no scheduler** — fixed.
   `backend/routes/marketplace/jobs.py:983` (`jobs_digest_daily_loop`) is
   started via `asyncio.create_task` in `backend/server.py:291`.

## Dead-end promises: destination lacks the affordance

1. **Auto-owner-nudge admin status/escape-hatch has no UI surface it
   documents itself as building.**
   `backend/routes/admin/chats_nudge.py:524-546` —
   `GET /admin/auto-owner-nudge/status` and `POST
   /admin/auto-owner-nudge/run-now`. The status endpoint's own docstring
   says its purpose is "so the admin Chats tab can render a 'auto-nudges on
   · 12h threshold' strip with counts," and run-now exists explicitly "so
   any bug shows up here without waiting 30 min." Neither is called from
   anywhere in `frontend/src` (grepped for `auto-owner-nudge`,
   `auto_owner_nudge`, `autoOwnerNudge` — zero hits). `ChatsTab.jsx` (the
   actual admin Chats tab) only wires the unrelated, working per-conversation
   `/admin/chats/nudge-owner` button — there is no status strip and no
   manual "run now" control. An admin has no way to see whether the
   background 12-hour auto-nudge sweep is running, or to force a run to
   debug it, despite the backend being built specifically to offer both.
   **Fix:** build the missing affordance — a small strip in `ChatsTab.jsx`
   reading `/admin/auto-owner-nudge/status` with a "run now" button hitting
   `/admin/auto-owner-nudge/run-now`, matching what the docstrings already
   promise. (Low urgency — internal ops visibility, not customer-facing.)

## Orphaned capabilities

1. **`GET /admin/marketplace/summary`** — `backend/routes/admin/marketplace.py:132`.
   No frontend caller (grepped the literal path — zero hits). Its own
   docstring says it fills "the counts the Overview row was missing (spec
   A1)," but the Overview row (`OverviewTab.jsx:83-87`) actually gets
   `active_services`/`businesses`/`open_requests` from `GET /admin/metrics`
   (`backend/routes/admin/core.py:169-175`), which computes the identical
   three counts independently in its `stock` block. The summary endpoint is
   dead, duplicate code — built for a screen that ended up sourcing the
   same numbers a different way. **Fix:** change the promise — delete the
   endpoint (or fold `admin/metrics`'s stock block to call it, if keeping
   one source of truth is preferred).

2. **`GET /properties/featured`** — `backend/routes/properties/browse.py:469`.
   No frontend caller. Its docstring explicitly says it "mirrors the
   client-side selection `Home.js#fetchFeaturedProperties` used to do," but
   `Home.js` was replaced by `pages/HomePreview.jsx` on 19 Sep 2026 (per
   CLAUDE.md), and `HomePreview.jsx`'s own in-file comment (line ~496-500)
   says the "Featured rentals" section was renamed to "Recently added"
   because "five of the live listings actually carry `is_featured`," and it
   now sorts newest-first. The current home page (`useHomeShowcase.js:71`)
   fetches `/properties?limit=200` and does client-side featured-first
   sorting — the exact "download the ENTIRE catalog" cost this endpoint's
   own comment says it exists to avoid. The admin "feature this listing"
   toggle (`ListingsTab.jsx`, `ListingsTable.jsx:204`) still works and still
   nudges sort order, so this isn't a broken admin control — just a
   purpose-built, cheaper endpoint nothing calls. **Fix:** either wire
   `useHomeShowcase.js` to call `/properties/featured` (restores the
   intended perf win) or delete the endpoint if 200-row fetches are
   accepted as fine now.

3. **`GET /businesses/{business_id}/listings`** — `backend/routes/marketplace/businesses.py:674`.
   Docstring: "What deactivating this business would hide — asked before
   doing it." No frontend caller. The actual deactivate-confirmation flow
   (`MyBusinessesTab.jsx:133-146`, `toggleActive`) shows a listing *count*
   in its `window.confirm()`, but that count comes from `biz.gig_count`
   (already present on the business list row), not from this endpoint,
   which would additionally list each listing's title/status. The
   confirmation goal is met a cheaper way; this endpoint's per-listing
   detail is unused. **Fix:** change the promise — delete the endpoint, or
   use it to upgrade the confirm dialog to name the listings instead of
   just counting them.

4. **`GET /admin/properties/{property_id}/blocks`** — `backend/routes/admin/properties_bulk.py:601`.
   Returns up to 500 historical admin-booked blocks for a property. No
   frontend caller. `ListingsTab.jsx:461-482` only ever shows/removes
   `property.active_admin_block` (the single current block, embedded on the
   property list row) — there is no "view block history" UI. **Fix:**
   change the promise (drop the endpoint) or add a small history view if an
   audit trail of past manual blocks has admin value.

5. **`POST /notifications/preferences`** — `backend/routes/notifications.py:14`,
   backed by the legacy `NotificationPreferences` model
   (`backend/models.py:240`, fields `rental_type`/`min_bedrooms`/`max_price`/
   `area`). No frontend caller anywhere. This looks superseded by the
   current `saved_searches.py` route and by
   `/marketplace/notification-preferences` (which
   `NotificationSettings.jsx:54-88` actually calls). **Fix:** confirm
   nothing else (an old email template, a mobile client) still targets it,
   then delete it and its dead model.

6. **`POST /marketplace/subscription/upgrade` and `/marketplace/subscription/cancel`**
   (`backend/routes/marketplace/subscription.py:386` and its sibling) — no
   frontend caller, and this one is *intentionally* dormant, not a bug:
   `MyGigsTab.jsx:434-436` says outright "upgrade() and cancelPro() lived
   here... Both endpoints still exist server-side, dormant," and
   `WhyList.jsx:210-213` explicitly replaced the old pricing-ladder section
   with a "Free to list" section because listing carries no subscription
   fee anymore. No copy anywhere promises a paid plan. Listed here only for
   completeness — not a defect.

7. **`POST /job-searches/send-digest`** — `backend/routes/marketplace/jobs.py:793`,
   admin-only manual trigger for the jobs digest loop. No frontend caller,
   no UI promises a "run digest now" button, and the equivalent requests
   digest (`requests_digest_daily_loop`) doesn't even have a manual-trigger
   endpoint for comparison. Legitimate ops/curl escape hatch, not a broken
   promise — nothing in the UI claims it exists.

8. **`frontend/src/components/home/BlocksHero.jsx`** — a fully-built,
   heavily-iterated Three.js hero (glass blocks tumbling into the site mark;
   its own header comment documents multiple rounds of feedback against a
   reference video, "Tzvi approved cropping on 9 Sep"). It is not imported
   anywhere (`grep -rn "BlocksHero" frontend/src` only matches its own
   definition). The live home page (`HomePreview.jsx:39,275`) uses
   `LoopHero` instead. Substantial, working code with no route. **Fix:**
   either wire it in behind `/home-preview` for the next round of
   experimentation (per the CLAUDE.md theme-experiment convention) or
   remove it — as-is it's dead weight that the next person touching the
   hero has to figure out is unused.

9. **`frontend/src/components/ui/gradient-text.jsx`** — a working, documented
   component (`motion`-based gradient-lit text), imported nowhere. Minor;
   likely a ported primitive waiting for a use, not a regression.

10. **Model fields checked per the audit's named-suspect list** (`faqs`,
    `kosher_certification`, `delivery_note`, `lead_time`, `payment_note`,
    `founded_year`) — **all have working editors.** `faqs` via
    `FaqEditor.jsx` (used in `CreateGig.jsx` and `EditListingModal.jsx`); the
    other four via `BusinessDetailsForm.jsx:312-315` (confirmed each is read
    into form state, sent on save, and rendered as a labelled input) and
    surfaced to buyers via `GoodToKnow.jsx`. Not orphaned — included here to
    show the check was done, not skipped.

## Verified working

Confirmed via static grep of both the control and its destination (route
exists, guard behavior matches, endpoint accepts the exact params/state the
UI can produce):

- **Route table** (`App.js:397-518`) — every route resolves to an imported
  component; the catch-all `*` → `NotFound` is last as required.
- **Auth return-to.** `ToAuth` (`App.js:73-76`) appends
  `?redirect=<path+search>`; `Auth.js:26-39` reads and honors it after
  login/signup, and preserves it across the login↔signup toggle
  (`Auth.js:635-638`).
- **Dashboard deep-links.** `?tab=`, `?edit=`, and `/dashboard/settings?section=notifications`
  are all read by `Dashboard.js:185-210` and `NotificationSettings.jsx:69-75`
  (confirmed fixed per the 2026-09-04 audit comment already in the code).
- **Property contact/chat.** `PropertyDetail.js#handleChat` (line 315) →
  `/chat/:id` with sublease_id preserved; login-gated with return path.
- **Gig/business contact.** `ContactChannels.jsx` renders WhatsApp / email /
  on-site per `contact_channels` from the server; on-site
  (`GigDetail.jsx#messageOnSite`, line 638) always routes to real chat
  regardless of `booking_mode`, including for stores (line 590-596).
  `BusinessPage.jsx:172` does the same.
- **Requests board contact.** `POST /marketplace/requests/{id}/contact`
  (`requests.py:907`) returns a chat deeplink; `RequestDetail.jsx:93-96`
  calls it; `GET /marketplace/requests/{id}/contact-whatsapp`
  (`requests.py:969`) is linked directly as an `href`
  (`RequestDetail.jsx:451`).
- **Requests board filters.** `condition`, `min_price`, `max_price`,
  `include_sold` round-trip through URL params
  (`RequestsBoard.jsx:402-463`) into the exact query params the backend
  validates (`requests.py:532-576`).
- **Gigs/services board filters.** `min_rating`, `min_price`, `max_price`,
  `response_time`, `languages`, `booking_mode`, `sort` (incl.
  `distance`), `lat`/`lng`, `max_distance_km`, `available_on`, `category` +
  `subcategory` all round-trip between `Services.jsx:58-226` and the
  `list_gigs` endpoint's full parameter set (`gigs.py:120-158`).
- **Legacy category slugs.** `?category=photography` and the other 8
  pre-migration slugs normalize before validation
  (`gigs.py:174-176`) and are covered by
  `backend/tests/test_legacy_category_slugs.py`.
- **Gig pause/resume.** `MyGigsTab.jsx` PATCHes `status` to `paused` and
  back; the backend's `GigPatch.status` pattern (`shared.py:645`) accepts
  exactly those two values from a provider and documents why `unpublished`
  is deliberately excluded from what a provider can set.
- **Booking cancellation.** `request-cancel` / `deny-cancel` /
  `approve-cancel` all called from `useBookingActions.jsx` and
  `BookingChip.jsx`, matching the ownership rules the backend enforces
  (`BookingChip.jsx:44-52` documents the exact 403 bug this used to have
  and how the current split avoids it).
- **Courier invites.** `accept`/`decline`/`leave` all posted dynamically
  from `DeliveriesTab.jsx:61`.
- **Admin request-reports moderation.** Both endpoints called and the tab
  is mounted and reachable from `AdminDashboard.js`.
- **Business completeness checklist.** All four actionable items (logo,
  description, service areas, one listing photo) open real, working editors
  (`BusinessDetailsForm.jsx`, `MyGigsTab.jsx`'s listings panel) that persist
  each field; the two non-actionable "receipt" items (name, category) are
  correctly rendered as non-buttons.
- **Email deep-links spot-checked:** jobs digest (`jobs.py:316-318, 574,
  909-946`) → `/services/jobs/:id`, `/notification-snooze`,
  `/dashboard/settings?section=notifications`, `/jobs-emails-off` — all

- **Availability-extend email link.** `GET /properties/availability/extend`
  (`availability_reminders.py:90`) is a JWT-scoped one-tap GET meant to be
  clicked from an email, not called from React — confirmed this is by
  design (GET chosen specifically so email clients can follow it without a

- **QR / crawler infra.** `/short-links/{slug}/follow` and
  `/og/business/{slug_or_id}` are hit by the `serve.json` rewrite rule and

- **Component orphan sweep.** 200 files under `frontend/src/components/**/*.jsx`
  checked; only `BlocksHero.jsx` and `gradient-text.jsx` (reported above)
  have zero importers.
- **Scheduled-loop sweep.** Every `*_daily_loop`/`*_weekly_loop`/
  `*sweep_loop`/`*nudge_loop`/`*cleanup_loop` function defined in
  `backend/routes/**` and `backend/utils/mention_email.py` has a matching
